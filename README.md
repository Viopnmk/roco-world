# roco-world

《洛克王国：世界》AI对战助手，阵容分析与回合策略

从零自建的《洛克王国：世界》图鉴与对战工具：数据管道、数据格式、页面代码全部自产。

## 数据来源

- BWIKI《洛克王国：世界》百科（wiki.biligame.com/nrc）社区维护的公开图鉴数据。
- 精灵数值、技能、进化关系等为游戏公开数据；本站只做整理与呈现。

## 数据管道（scraper/）

数据源不在百科页面正文里，而是存放在 Lua 数据模块中，分基础层与赛季层（S5）两层。管道分两步：

```bash
# 1. 拉取原始数据模块到 scraper/raw/（带断点续拉与重试）
python3 scraper/fetch_nrc.py

# 2. 解析 Lua 表、解码赛季分片、按 key 合并，生成站点数据
python3 scraper/build_data.py
```

- `scraper/lua_parse.py`：Lua 表字面量解析器（数据模块是 `return { ... }` 形式）。
- `scraper/fetch_nrc.py`：通过 MediaWiki API 拉取 15 个数据模块。
- `scraper/build_data.py`：合并规则与 BWIKI 自身的赛季适配器一致（赛季数据按 key 覆盖/追加基础层；SeasonLearnsets 给旧精灵追加赛季技能石）。
- `scraper/fetch_typechart.py`：单独拉取克制计算器的数据模块 `模块:Pets/data/Types`，转置并校验后生成 `web/data/typechart.json`（见「对战与配队」一节）。
- `scraper/fetch_natures.py`：单独拉取性格页的数据模块 `模块:Natures/data`，生成 `web/data/natures.json`（见「培养方案」一节）。

## 数据格式（web/data/）

由管道生成、供页面直接读取的 JSON，字段口径自定：

- `pets.json`：精灵。每条含图鉴编号、显示名、物种名、属性、六维种族值与总和、特性、身高体重、图鉴描述、栖息地、赛季、拼音搜索键、头像/立绘文件名，以及学习面（等级技能 / 技能石 / 血脉技能，均为技能名）。
- `skills.json`：被精灵引用的技能与特性。含属性、分类（物理 / 魔法 / 变化 / 特性）、威力、能耗、描述。
- `evolutions.json`：进化链。含各阶段精灵、进化等级、特殊进化条件与首领化分支。
- `typechart.json`：属性克制表。`{攻方属性: {守方属性: 倍率}}`，18×18 全格，由 `scraper/fetch_typechart.py` 从 BWIKI 克制计算器的数据模块生成（见下「对战与配队」）。
- `natures.json`：性格表。`[{name, plus, minus}]`，plus/minus 为六维键名（hp/atk/def/spa/spd/spe），由 `scraper/fetch_natures.py` 从 BWIKI 性格数据模块生成（见下「培养方案」）。

当前数据量（2026-11-17 管道实跑）：精灵 662、技能与特性 861（招式 599 + 特性 262）、进化链 340。

## 图鉴本体（web/）

单文件 SPA（`web/index.html`，内联 CSS/JS、无外部依赖、无框架），静态托管即可运行，Hash 路由：`#/` 为列表、`#/pet/<id>` 为详情、`#/battle` 为对战模拟、`#/team` 为 AI 配队、`#/squads` 为阵容推荐、`#/train` 为培养方案。顶部导航六页互通，详情页可一键把精灵送进对战、配队或培养。

- **列表页**：按名字 / 物种 / 拼音 / 编号即时搜索；18 种属性 chips 单选筛选；赛季筛选（全部 / S1–S5 / 无赛季）；排序（图鉴编号、总和升降、六维各自降序）；卡片网格（头像、编号、属性徽章、总和），图片懒加载。
- **详情页**：立绘大图、种族值六维条形图、特性名与描述、身高 / 体重 / 栖息地 / 图鉴描述；进化链（含首领化分支，同 key 的多条分支记录在前端按 pet 去重合并展示）；技能表分等级技能 / 技能石 / 血脉技能三组，点行展开描述，属性 / 分类 / 威力 / 能耗均查自 `skills.json`。
- **图片**：`scraper/fetch_images.py` 通过 MediaWiki API 把头像 / 立绘文件名批量解析成 patchwiki 直链，生成 `web/data/images.json`（1264 个文件、662 只 × 头像+立绘全覆盖）。前端优先用直链，缺失或加载失败时回退 `Special:FilePath`，再失败显示首字占位块。图片有更新时重跑：

```bash
python3 scraper/fetch_images.py
```

本地预览：

```bash
cd web
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000/
```

## 对战与配队（第 3 期）

页面在同一个 `web/index.html` 里：`#/battle` 对战模拟、`#/team` AI 配队，逻辑全部自写。

### 属性克制表（web/data/typechart.json）

- 来源：BWIKI「克制计算器」背后的结构化数据模块 `模块:Pets/data/Types`（BWIKI 的 `Module:TypeData` 从该模块组装计算器，模块注明按当前游戏数据生成）。用 `python3 scraper/fetch_typechart.py` 拉取并转置成攻方导向矩阵，原始模块缓存在 `scraper/raw/模块_Pets_data_Types.txt`。
- 本作的倍率只有四档：克制 ×2、双重克制 ×3、抵抗 ×0.5、双重抵抗 ×0.25。**没有属性免疫（不存在 ×0）**：例如电打地、幽灵打普通都只是 ×0.5，与经典宝可梦克制表不同，一律以本模块数据为准。
- 双系合并用「步进规则」：每个守方属性贡献一步（被克制 +1、被抵抗 −1），合计 +2→×3、+1→×2、0→×1、−1→×0.5、−2→×0.25。该规则已用模块自带的 102 条双系组合（1836 格）全量验证、零误差；模块未收录的组合（如毒+幻）也按此规则计算。
- BWIKI 的「幽系」在本站统一写作「幽灵」。

### 对战模拟（#/battle）

- 选攻方精灵 → 从它 learnset 全部技能（去重）里选一招 → 选守方精灵，即时算伤害；结果含克制倍率、本系加成、伤害占守方体力种族值的百分比与预计击破次数、每点能耗伤害。
- **伤害公式（估算口径）**：`伤害 = 威力 ×（攻击种族值 ÷ 防御种族值）× 克制倍率 × 本系加成`。物理技能用物攻/物防，魔法技能用魔攻/魔防；本系加成 = 技能属性与攻方任一属性一致时 ×1.2，否则 ×1。变化类技能显示「无直接伤害」并展示技能描述。
- 假设与局限：BWIKI 未公开本作完整伤害公式，以上为本站自定的透明估算口径；只用种族值，不含等级、个体值、特性与状态增减，结果仅供配招参考。

### 6v6 PVP 分析（#/battle 上方页签，默认页）

对战页上方有页签切换：「6v6 分析」（默认）与「1v1 计算」（即上面的对战模拟，原样保留）。6v6 分析把单挑计算器升级为整队对局分析：

- **队伍互通**：我方 / 敌方各最多 6 只，与配队页共用同一份本机存档（`localStorage` 键 `roco-world-team-v1`，同一组 `team.mine / team.foe` 数据）——配队页组好的队伍到对战页直接能用，反之亦然。不满 6 只也能分析，按现有只数计算并给出提示。
- **出招口径（代表招）**：每只精灵对每个目标，从其全部可学技能（等级 / 技能石 / 血脉三组去重）里按与 1v1 完全相同的伤害公式逐招计算，取伤害最高的一招为代表招；物理 / 魔法按技能分类取对应攻防，变化类等无威力技能不参与。
- **对位矩阵**：6×6 表格（我方行 × 敌方列），每格为代表招伤害占目标体力种族值的百分比与击杀标记（1 击 / 2 击 / 3 击+），按 ≥100% / 50–99% / <50% 三档配色，手机上可横滑；另附反向小结：敌方每只对我方的最高单体伤害 % 与能 1–2 击带走我方的只数（按威胁排序）。
- **胜负预测**：总判定（我方优势 / 均势 / 敌方优势）+ 我方倾向百分比，由四项按权重加权合成——击杀覆盖 35%（双方各有几只处于对方 2 击斩杀线内）、速度控制 20%（均速份额，附速度线逐位先手数）、种族值总和 20%（平均总和份额）、属性压制 25%（与配队页「对敌压制」同一口径）。每项附对比条与一句话解释。
- **文字分析**：模板化生成的中文分析师点评，全部引用真实计算数字：总体判断、我方王牌（对敌总威胁最高者及它能带走的名单）、最大威胁（敌方最危险者及受威胁名单）、应对建议（针对每只高威胁敌方，给出能反手 1–2 击带走它且挨打最轻的我方应对者）、首发建议（速度 + 覆盖综合最优者及理由）。
- **性能**：36 个对位 × 每对位遍历攻方全部可学技能，本机实测分析耗时约 5ms，手机上秒出；不做任何指数级搜索。

### AI 配队（#/team）

- 我的队伍最多 6 只（搜索加入、可移除，`localStorage` 保存在本机）；可选填敌方队伍（最多 6 只）。
- 评分 0–100，全部为自写规则，每项附人话解释：
  - **打击面覆盖**（无敌方时权重 35%）：全队有威力技能的属性集合，对 18 种单系守方逐一取最高克制倍率；每克制（×2 起）一种记满分、等倍一种记三成、被抵抗记 0 分（全克制 100 分、全等倍 30 分）。
  - **防御抗性**（30%）：弱点重叠（被同一属性克制的只数越多扣越狠，占 60 分）+ 人均弱点数（占 40 分）。
  - **种族值总和**（20%）：全队平均总和，按全图鉴极值（最低～最高）线性归一。
  - **速度线**（15%）：平均速度占 70% + 最快速度占 30%，均按全图鉴最快速度归一。
  - **对敌压制**（仅填敌方时计入，权重改为 打击面 25% / 防御 25% / 种族值 15% / 速度 10% / 对敌 25%）：我方打敌方每只的平均最高倍率与敌方反打我方的平均最高倍率之差，`50 +（我方 − 敌方）× 50` 截断到 0–100。
- **补位推荐**：队伍不满 6 只时，遍历全图鉴逐只试补、重算总分，取提升最大的 5 只；理由优先写新增的超效打击面与堵住的半伤短板，其次写抗性摊薄或面板/速度拉升。队伍满员时改为提示现存打击面短板。

## 培养方案（第 5 期，#/train）

选一只精灵，生成一张培养卡：携带技能 ×4、性格推荐、改血脉推荐、个体值优先。详情页有「🧬 看培养方案」入口（`#/train?pet=<id>` 深链预选）。全部推荐由本站模型按规则现算，引用真实数据，不是官方攻略，仅供参考。

### 性格数据（web/data/natures.json）

- 来源：BWIKI「性格」页的数据模块 `模块:Natures/data`（页面经 `模板:性格` → `模块:Natures` 渲染，数据本体在该模块中），用 `python3 scraper/fetch_natures.py` 拉取生成，原始模块缓存在 `scraper/raw/模块_Natures_data.txt`。
- **以 BWIKI 实测为准，共 30 种性格**：6 种「提升属性」× 5 种「降低属性」的完整矩阵，每种一项 +10%、一项 −10%，**包含生命项**（可以 +生命或 −生命），**没有中性（无增减）性格**。这与网上流传的旧版 25 种性格表（无生命项、带 5 种中性）不同：旧表中的孤僻、淘气、无虑、保守、沉着、狂妄、随性等名字在本作不存在，坦率（+物防 −生命）、害羞（+魔防 −魔攻）也并非中性，一律以 BWIKI 数据为准。

### 推荐口径（模型生成）

- **携带技能 ×4**：候选 = 该精灵 learnset 三组（等级 / 技能石 / 血脉）去重并集。攻击招按「有效威力 = 威力 × 本系加成 1.2 × 攻项匹配度（该招对应攻项 ÷ 双攻较高项）」排序，先保 1–2 招本系主攻；第 3 招补打击面（能 ×2 打中「克制本精灵的属性」记 3 分/个、新覆盖属性记 1 分/个）；第 4 招优先描述带回复 / 护盾 / 强化等关键词的变化类辅助招，没有合适的用次优攻击招补齐。每招标注来源（等级 / 技能石 / 血脉系别）、能耗与一句话理由。
- **性格推荐**：先按种族值画像定 +/− 组合，再查性格表得名。高速输出型（速度 ≥95 且主攻 ≥90）→ +速度 −废攻；慢速输出型（速度 <70）→ +主攻 −速度；中速输出型 → +主攻 −废攻；坦克型（双攻都 <95 且双防/体力突出）→ +较高防 −较低攻。给主推与备选各一，理由引用种族值数字。
- **改血脉推荐**：候选 = 该精灵 bloodline 池每条（条目自带血脉系别），按其技能属性打分：×2 克制「克制本精灵的属性」的个数 ×3（反打弱点）+ 新增打击面数 + 威力/100（+本系 0.5）。给首选与备选，展示血脉系别、解锁技能与理由。**改血脉只会让精灵在 15 级多学一个该系血脉技能，不改变精灵自身属性，也不会改变它被克制的关系。**
- **个体值优先**：按画像给主攻 / 速度 / 生存三类打分取前三项 chips 展示（主攻项恒第一；速度按速度线分档；生命与双防按数值分档，坦克型额外加权防御与生命）。

## 阵容推荐（第 6 期上线，第 7 期扩充至 12 套 + 配合模型，#/squads）

模型按流派自动组好的 6 只队伍，卡片流浏览（阵容名 + 6 只头像横排 + 一句话简介），点开展开成员角色与入选理由、配队四项评分（复用 `#/team` 的 `scoreTeam`）、打击面覆盖与弱点 TOP、打法说明。每套阵容可一键「设为我方队伍」（写入与配队/对战页共享的 `localStorage` 队伍 `roco-world-team-v1`）或「去对战分析」；成员行带「🧬 培养」链接直达 `#/train?pet=<id>`。

### 第 8 期改造：48 小时自动轮换（自由混搭 + 强度优先）

第 6/7 期的 12 套固定阵容已从页面下架；页面改为只渲染 `web/data/rotation.json` 里的**本轮 3 套**，页首显示本轮生成时间与下次更新时间，数据加载失败时显示友好提示与重试按钮（不白屏）。构建器与配合模型全部保留，降级为轮换生成器的战术来源。

- **生成器**：`tools/gen_rotation.mjs`（Node，无依赖）。它抽取 `web/index.html` 的内联脚本在 vm 里运行，复用页面同款模型函数（`scoreTeam` / `typeMult` / `effPower` / `squadLinks` 及证据表 / 全部旧构建器），再叠加本期新战术构建器与轮换逻辑——页面与生成器永远同一套口径。一条命令完成一轮：

```bash
node tools/gen_rotation.mjs        # 仓库根目录执行；ROT_DIAG=1 可跑全战术可达分诊断
```

- **定时任务**：由外部 cron 每 48 小时在仓库根目录调用上面这条命令，生成后照常提交推送（Cloudflare Pages 自动部署）。不依赖用户打开网页。
- **rotation.json 结构**：`{ round, generatedAt, nextAt, squads[3], prevSquads }`。每套含 `tactic / title / emoji / tag / intro`（核心思路）、`score / scores`（四项评分）、`members[6]`（id / 名称 / 分工 / 理由）、`links`（配合链，结构与 `squadLinks` 输出相同）、`pros / cons`、`playbook`（第 9 期战术手册，见下节）。`prevSquads` 是上一轮 3 套的成员 id 列表，供下一轮避重复。

### 第 9 期：阵容战术手册（playbook）

每套轮换阵容在详情页「配合链」之后多一份 **📖 战术手册**，回答「这队具体怎么打」。`playbook` 结构：`{ lead: { id, name, reason }, phases: [ { key, title, text } ×5 ], movesets: [ { id, name, moves: [ { name, type, category, power, energy } ×4 ] } ×6 ] }`。

- **起手（lead）**：统一打分选出，不按战术名硬编码——分数 = 速度 ×0.6 + 耐久 ×0.06 + 开场型资源权重（天气设定 150 / 供能 80 / 蓄势特性 65 / 状态或印记挂载 55 / 先手招 35 / 入场增益 30）。所以天气队自然是天气手起手、能量队自然是供能者起手；`reason` 引用它真实的特性/技能名与效果短摘。蓄势与入场增益只计分、不作第一回合动作（蓄势要在场下攒），第一回合动作优先级 = 天气 > 供能 > 挂载 > 先手 > 纯火力压血。
- **五段剧本**（模板参数化，每段 1–3 句，落到具体成员与真实技能/特性名）：`open` 开局 = 起手者的第一回合动作与期望收益；`early` 第一阶段 = 围绕本套配合链第 1、2 条展开（联动骨架直接引用 `links`，不另编新联动）；`mid` 中期 = 换人轴心（耐久为主、带减伤/回复/应对手段者）+ 针对全队最怕属性（`weakCounts` 的 weakTops）的联防答案（抗性成员或反打属性）+ 累积机制的滚雪球路径；`late` 后期 = 收割手（速度+有效威力最强，自损招如「彗星」不作代表招）+ 击杀收益/吸血残局核心；`comeback` 逆风局 = 起手被克制时的顶替者（抗起手弱点属性且能站场）、拖字诀资源（降属性/能耗压制/挂状态/回复，取真实存在的第一个）、配合链翻盘点。
- **成员推荐配招（movesets）**：直接调用页面 `buildCard(pet)` 的 `moves` 输出，与培养页同款同源、口径一致（手册里注明同源）。
- **生成与 enrich**：默认生成新轮次时自动产出 `playbook`；另有补数模式，只给当前轮次补手册、其余字段（成员/round/generatedAt/nextAt/分数）一字不动，且幂等（重复运行结果逐字节一致）：

```bash
node tools/gen_rotation.mjs --enrich   # 给现有 rotation.json 的当前轮次补 playbook
```

- **文案红线**：剧本里出现的每个技能/特性名必须属于所指精灵（特性 = `ability` 字段、技能 ∈ learnset），每个成员名必须是本队成员；本作不存在的机制（睡眠/反伤等）绝不出现在剧本里。验收有独立断言脚本逐句复核（按句切分，句中「」引用的名字必须属于该句点名的成员）。
- **轮换规则**：种子由上一轮 `generatedAt` + 轮次号派生（同输入同输出、可复现）；每轮先在新战术里保底选 1 套，再按洗牌序从全战术池补满 3 套，战术互不相同；与上一轮每套重合 ≤2 只、本轮 3 套两两重合 ≤2 只。放宽顺序固定：先换战术组合 → 再把重合放宽到 ≤3 并在该套上标注 `relaxed: true`（页面不展示）→ **绝不降质量门槛**；凑不齐 3 套达标阵容时生成器报错退出、保留旧文件，宁缺毋滥。
- **强度优先（best-of-N）**：每个战术每轮做 10 次「构建（种子抖动/扰动）→ 避重复修复 → 局部爬山优化」，取 `scoreTeam` 综合分最高的一版入选。质量门槛 ≥58 是下限不是目标，入选尽量 ≥60；候选池向高种族值 / 高有效威力倾斜。实测全战术可达分 65–81（见下表），无一战术需要单独放宽门槛。
- **战术池（18 个）**：天气 4（雪/雨/沙暴/雷鸣）、机制 5（印记/奉献/吸血/能量/首领）、基础 3（火系/高速/坦克），加本期新增 6 个自由混搭/新打法：

### 流派清单与入选口径（贪心组队，同一进化家族 + 同一物种的不同样子只取一只）

- **天气队 ×4**：按「天气手 1 + 受益者 2 + 同系输出 2 + 补盲 1」构成。天气手 = 能学开天气招（或带开天气特性）的精灵；受益者 = 带受益特性或能学受益技能的精灵；同系输出按攻项与总和选；补盲按「新增超效打击面 + 反打全队最怕的属性」从全图鉴选。
- **火系队**（单系池 62 只）：火系输出 3（物/魔侧错开）+ 火系前排坦克 1 + 补盲 2。
- **高速队**：速度 ≥100 的候选按「速度 ×3 + 总和 + 先手/迅捷招加分」选 5 + 补盲 1（先手/迅捷招据技能描述中的「先手+1」「迅捷」判定）。
- **坦克队**：耐久（体力+物防+魔防）≥380 的池子里选主坦/副坦 2 + 真回复技能最多的续航核心 2 + 耐久输出 2。真回复口径：变化类技能中描述为回复生命/体力或吸血的招；满图鉴普及的「减伤应对」姿态招不计（几乎人手一打、不区分队伍）。
- **印记队**（第 7 期，机制队）：星陨印记的「引爆核心 1（消费端特性/技能最全者）+ 挂印记 2（单只 ≥2 个施加招）+ 印记受益 1 + 幻系输出 1 + 补盲 1」。核心实测为迷迷箱怪/祭礼巨像一线：施加与消费同体或互补。
- **奉献队**（第 7 期，机制队）：奉献「产出/受益」池贪心选 4（产出与消费双修者优先）+ 虫系输出 1 + 补盲 1。跨属性混编（虫/草/武/恶等），不锁虫系。
- **吸血队**（第 7 期，机制队）：全图鉴吸血来源 ≥2 个的池子（110 只，跨属性）按「来源数 ×60 + 输出」选吸血核心/输出 4 + 吸血坦克 1 + 补盲 1。
- **能量队**（第 7 期，机制队）：供能手 1（富养化/养分回流/加大功率）+ 蓄能王牌 1（入场前蓄势特性）+ 大招手 2（握有能耗 ★7–10 的大招）+ 供能手 1 + 补盲 1。展示口径剔除能耗 ≥30 的数据异常招（如抛石 ★30）。

### 配合模型（第 7 期）：配合分 + 配合链

组队贪心加入**配合分**：候选与已选成员之间存在可验证的配合关系时加分——天气（开天气 × 受益）、印记（施加 × 消费）、奉献（产出 × 受益）、能量（供能 × 高能耗大招）、蓄势（蓄能特性 × 对应系别技能喂养）、吸血（多来源同体）。每套阵容详情里给出 2–4 条**配合链**，格式为「A 的特性/技能「X」→ B/全队：说明 + 出处原文短摘」。

**证据原则（铁律）**：配合链里出现的每个特性/技能名，都由判定函数从该精灵的真实数据里取出（特性 = 其 `ability` 字段、技能 = 其 learnset 三组之一），并在验收断言中逐条用原始 JSON 独立复核——出处对不上即整期不合格。引文为 desc 首句原文。
